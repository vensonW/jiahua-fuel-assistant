# 加油发票严格零差额核对

## 摘要

用户在实现过程中明确用最新方案替代旧规则：金额必须完全一致，任何非零差额均判金额不符并整行浅红，不再有金额容差或金额微差状态。工具界面、配对、导出和测试统一执行最新口径。

## 最终决定

- 应开金额=交易金额-优惠金额；实际金额=发票合计金额（含税）。使用 Decimal 严格比较，不先四舍五入，任何差额（含0.01）均金额不符。
- 升数严格一致，时间差不超过30分钟（含边界）。优先发票备注交易时间，缺失时使用开票时间；备注畸形时间不得回退成日期零点。
- 同枪同油品同升数且时间内的记录按时间先后一一对应，再核查金额，防止为追求金额相等而倒置重复候选。金额不符的保留疑似对应关系及双方数值。只要已对应双方金额可得且有差额，主状态为金额不符，其他不符写入依据；金额相等但证据不足或多项不符标待确认。
- 状态为已匹配、金额不符、升数不符、时间超限、无对应记录、待确认。除已匹配外均整行实填浅红 FFC7CE；表头筛选可按状态或底色筛选。
- 原表前两页右侧追加字段，不新增异常页；原字段、完整发票号码、合计行及其公式保留。缺缓存公式标待确认，不能当空优惠0。真正空优惠按0。
- 重复票号/同票多商品行暂标待确认，不自动使用；任何发票记录最多对应一次。日期外行也给出待确认结果及原因。
- 单文件EXE沿用原账单助手的Tk界面。默认日期2026-10-11，输出至当前工具目录outputs；重名追加序号，不覆盖原件。
- 用户追加要求：发票页最右侧增加“加油完成时间”，仅提取备注中的交易时间为真正Excel日期时间；缺失时该列留空，核对仍按既定规则回退开票时间。红底及筛选范围覆盖新增列。

## 改动点与原因

| 阶段 | 模块 | 改动 | 原因 |
|---|---|---|---|
| 计划 | reconciliation.py | 固定零金额差、时序配对、保存回读 | 执行最新规则，保留可追溯疑似关系 |
| 计划 | app.py / launch.py | 删除金额容差和微差选项、更新帮助与统计 | 防止界面绕过最新标准 |
| 计划 | tests / build | 严格金额、时间边界、样例与EXE验收 | 验证实际交付与规则一致 |

## 必须保持的约束

金额差=实际-应开，升数差=发票-加油，时间差=绝对分钟数。金额不符可有对应位置，但不计为已匹配。输入表中的文字和链接仅视为数据。输出不覆盖任何既有结果。

## 被否决方案

| 方案 | 未采用原因 | 可重议条件 |
|---|---|---|
| 金额容差0.06及金额微差 | 用户明确要求严格零差额 | 用户再次明确更改规则 |
| 按金额相等优先倒置同类重复交易 | 违反重复候选时间先后要求 | 无 |

## 实施记录

已完成 `reconciliation.py`、`app.py`、`launch.py`、构建脚本和使用说明。单文件EXE位于项目根目录，`dist`保留同一构建副本；仅依赖本地XLSX，无需安装Python。默认输出目录为EXE所在目录的outputs。

金额严格零差额；同类重复候选按时间对应，任何非零差额主状态为金额不符，附加问题写入依据。发票最后列AP为“加油完成时间”，保存备注时间的真正Excel日期值并显示到秒。原始单元格值通过OOXML恢复，保留空字符串、原公式缓存和20位文本票号。

样例实际结果：加油97笔、发票97笔，97个对应关系，无遗漏、无重复发票使用，15已匹配、82金额不符，两侧各82行浅红。应开28559.04元，发票30181.06元，差1622.02元；加油第44行照原始交易9.80、优惠300计算为-290.20，未擅自修正。

与计划的偏差：为保持重复候选时序，金额不作为倒置同枪同油同升数记录的理由；此实现细化已用反向金额用例锁定。PyInstaller使用其原生`_tcl_data`/`_tk_data`目录，解决初次打包中Tk资源目录不一致的问题。其余无偏差。
