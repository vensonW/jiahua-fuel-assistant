# 加华油站小助手

界面采用浅蓝底色、白色内容卡片和蓝色按钮，仅保留系统标题栏中的工具名称。窗口、详情和任务栏使用透明底加华星标；EXE 文件图标采用原来的红底 GAWA 英文字样。

将加油明细与发票逐笔核对，在加油明细异常原行标出浅红底并写入末列“失败原因”；付款类型为“记账卡”的记录整行标黄，匹配失败切页同样标黄。失败详情另存为 `logs` 文件夹中的 `.log`。结果 Excel 保留原始切页，另增所选站点的发票切页及“匹配成功”“匹配失败”“发票未配对”切页；原文件保留。

GitHub 仓库包含源码、测试、品牌资源和构建脚本。原始业务工作簿、结果文件和 EXE 保留在本地，不随代码上传；从仓库获取代码后，请自行提供输入工作簿，按下方说明运行源码或打包 EXE。

## 使用 Windows 工具

1. 双击当前目录的 `加华加油与发票核对助手.exe`，运行 EXE 无需安装 Python。`dist` 内保留构建副本。
2. 点击“数据工作簿”旁的“浏览…”，选择加油及发票 `.xlsx` 文件；再点击“发票审核单”旁的“浏览…”，选择 `invoiceList_*.xlsx` 原文件（不要选择 `~$` 开头的 Excel 临时文件）。两项都记住上次选择的有效路径。工具按表头识别加油明细与发票切页，并从加油明细“交易时间”读取最早、最晚日期。待站点识别完成，在“审核站点”勾选一个或多个站点，也可全选；只核对所选站点。
3. 选择工作簿后，开始、结束日期自动设为加油明细最早、最晚日期；日历只能选择这段日期。勾选“指定时刻”后可选择时、分、秒。只选日期时，开始按当天 `00:00:00`、结束按当天最后一刻处理，包含两端边界；点击“全部加油日期”可恢复完整加油日期范围。所选时间超出加油明细日期范围或与发票资料区间不重叠时直接提示，不开始核对。
4. 发票审核单备注标为“被红冲”的原蓝票，以及审核单中明确作废/无效的票，在核对前排除：不参与配对，也不进入站点切页或“发票未配对”切页；原始发票切页保持不变。确认输出目录，默认保存到工具所在目录的 `outputs` 文件夹，可通过“浏览…”另选位置。并发工作数默认为 `20`，可在界面选 `1`—`32`；筛选时间间隔默认 `60` 分钟，可输入 `0`—`525600` 分钟。
5. 点击“开始核对”，读取阶段显示动态进度；匹配阶段按加油记录显示每轮已处理笔数（如 `5/97`），生成、校验工作簿及保存日志后进度条才会填满。候选查找分三轮并发进行，结果仍按时间顺序一对一配对。完成后汇总区域及 `.log` 均显示核对耗时。程序“匹配失败”切页只显示核对未通过的加油明细及详细原因，可在“查找原始行号”输入如 `1698` 快速定位；“核对状态”下拉框仅列出加油明细出现的失败状态。成功与失败预览均按交易时间从早到晚显示，缺失时间的排在最后。“匹配成功”切页每对显示一条。点击“对应记录位置”可打开结果 Excel，双击其他列查看完整内容。
6. 点击“打开结果工作簿”，可在加油明细表头按底色筛选浅红色异常行或浅黄色记账卡行；点击“打开核对日志”只查看失败记录。Excel 不增加核对状态列，按状态筛选在程序失败切页中完成。

预览筛选不会减少导出记录。“仅显示加油异常”只显示加油侧未匹配记录，包含付款类型为记账卡的黄色记录；发票异常保留在结果工作簿及日志中，发票工作表不新增底色。结果工作簿保存在输出目录，日志保存在其 `logs` 子目录，两者使用相同文件名主体；其中任一文件重名时，整对文件自动追加序号，不覆盖已有工作簿。新核对成功后，自动删除同一输入工作簿的旧核对 `.log`，包括输出目录根部的旧版日志，保留其他文件和当前日志。使用帮助位于设置操作行。

## 核对规则

- **应开票金额＝交易金额**：交易金额已扣除优惠，不再重复扣减。与发票“合计金额（含税）”按原始数值严格比较，不先四舍五入；任何非零差额，包括 `0.01` 元，都判为“金额不符”并将加油原行标浅红底。优惠金额仅供展示，不参与核对。
- 加油升数与发票数量必须完全相同，任何升数差额都不通过。
- 加油明细页“交易时间”与发票备注“交易时间”相差应在 **0—所设筛选时间间隔内**，默认 60 分钟，包含边界；如果发票交易时间比加油明细交易时间更早，状态显示“时间先后异常”，失败原因列出两处原始时间与相差时长。发票“开票时间”单独保留。
- 备注缺少结束时间时，允许使用开票时间辅助核对，并注明时间来源；“加油结束时间”仍留空。备注有时间但格式无效时标为待确认，不能把它当作缺失后直接回退。
- 从发票备注解析出的交易时间作为加油结束时间，供核对、程序预览和日志使用，同时写入结果 Excel 发票页“备注”右侧的“交易时间”列。备注缺失或无效时该列留空，不用开票时间代填。
- 优先根据备注油枪号及结束时间，结合加油表枪号、开始时间、油品和升数寻找对应记录；多油站数据须确认油站相符，不跨站配对。
- 同枪号、同油品、同升数的重复候选按双方时间先后一一配对，并注明“按时间顺序推定”；不能为了金额相等调换顺序。有多余发票候选时，在不减少配对数或打乱顺序的前提下，优先金额、升数和时间均符合的发票，而不是只选时间最近的一张。每笔加油记录、每笔发票记录最多使用一次。
- 其他信息能支持对应、但金额或其他规则不符时，可保留疑似对应位置及差额供核查；**疑似对应不计为“已匹配”**。
- 无法可靠判断、必需字段异常、同一发票多行或重复票号等情况标为“待确认”。所选时间段之外的记录直接跳过，不计入核对数量、异常、预览或日志；原始切页中的数据仍保留。
- 同一记录存在多项问题时，全部写入配对依据；只要金额存在差额，主状态显示“金额不符”。

| 核对状态 | 含义 |
| --- | --- |
| 已匹配 | 金额、升数完全相等，结束减开始不超过所设时间间隔，且配对依据成立 |
| 金额不符 | 存在对应或疑似对应，但实际发票金额与应开票金额存在差额 |
| 升数不符 | 存在疑似对应，但升数不同 |
| 时间超限 | 存在疑似对应，但结束减开始超过所设时间间隔 |
| 时间先后异常 | 发票交易时间早于加油明细交易时间 |
| 无对应记录 | 未找到可靠对应记录 |
| 待确认 | 证据不足、字段异常、同票多行、重复票号等情况 |

除“已匹配”外，加油明细对应原行均标浅红底，付款类型为记账卡的行改用浅黄底；已匹配且付款类型为记账卡的行也标浅黄底。发票页不新增标红。时间段外记录不核对、不标色，也不写失败原因。

## 结果工作簿

结果工作簿保留全部原始工作表及原始行顺序，在加油明细页末尾新增“失败原因”列，发票页“备注”右侧插入“交易时间”列；未选站点或所选时间段外的原始行仍保留，但不参与本次核对。每个所选站点另增以站点名称命名的切页（不追加“发票”），按**开票时间**从早到晚复制时间段内的发票行，无有效开票时间的排在最后；核对时的对应发票位置和失败原因均引用该切页排序后的行号。

“匹配成功”页每对成功记录占一行，含站点、油枪、油品、加油量、交易时间、金额、发票号码及对应位置。“匹配失败”页只保存未通过的加油明细记录，列出状态、原因、金额及升数差异等；原始行号和对应位置可点击跳转。这两页按加油交易时间升序，行号仍指向未排序的原始加油页。“发票未配对”页保存所选站点在时间段内未与加油明细配对的发票原始列，另列发票切页行号、油站、核对状态与未配对原因；该页按发票备注交易时间升序，行号则指向按开票时间排序后的站点切页。备注相同但票号不同的重复开票，未配对原因显示“重复发票：跟对应行是同一单”。字段异常的发票仍在该页列出，时间段外的发票跳过。新增切页不受界面筛选影响，首行均显示发票原切页的“资料区间”（含起止时间）；原切页没有该行时显示本次核对区间。其他原始字段、行高、列宽及已有批注保留，完整卡号和发票号码按原数据保留。

加油明细的异常原行（含失败原因列）整行标浅红底，付款类型为记账卡的记录无论匹配结果均标浅黄底，并在表头启用底色筛选；匹配失败切页新增“付款类型”列，付款类型为记账卡的行也标黄。原表列名为“付款方式”时直接从该列读取。发票页除新增交易时间列外，不新增标红、筛选、隐藏行列或冻结窗格。

## 独立核对日志

每次核对同时输出 UTF-8 编码的 `.log`，保存在结果 `.xlsx` 所在目录的 `logs` 子目录，文件名主体相同。日志只记录匹配失败的两侧记录，包含状态、失败原因、对应位置、完整卡号与发票号码、付款类型、枪号、油品、三个时间、金额差、升数差、时间差和配对依据。

“已匹配”记录在程序的“匹配成功”切页按每对展示；程序“匹配失败”切页只展示加油明细的异常状态、失败原因、疑似对应和三个时间，其中“加油明细切页-交易时间”来自加油原表，“发票-交易时间”来自发票备注。状态筛选只列出加油明细出现的失败状态。

失败页显示“异常数量 / 加油总笔数”，成功页显示“成功数量 / 加油总笔数”。异常笔数为加油总笔数减成功笔数，失败页另显示筛选后的行数。结果工作簿的“匹配失败”页只保存加油明细失败记录，“发票未配对”页保存没有配对的发票，日志仍保存两侧失败记录。

- 金额差＝实际发票金额－应开票金额。
- 升数差＝发票升数－加油升数。
- 时间差＝加油结束时间－开始时间，以有符号分钟数展示；备注缺失时按注明的开票辅助时间计算。
- Excel 加油页支持按浅红底或浅黄底筛选；按状态筛选在程序预览中完成。
- “对应”按一对加油与发票计数；异常数只统计加油侧，发票侧不新增底色。

## 2026 年 10 月 11 日样例

旧版基于“交易金额－优惠金额”的统计不再适用。请导入实际工作簿重新核对；新规则直接以交易金额与发票金额比较，并要求加油量与发票数量完全相等。

核对 2026 年 10 月 1—7 日需要导入该期间实际数据，再将开始日期设为 `2026-10-01`、结束日期设为 `2026-10-07`；现有 10 月 11 日样例不能替代该期间数据。

## 源码运行与维护

使用带 Tkinter 的 Python 环境，在项目目录安装依赖后启动：

```powershell
python -m pip install -r requirements.txt
python launch.py
```

命令行也可执行核对：

```powershell
python launch.py --input "中南加华加油和开票数据核对.xlsx" --output-dir "outputs" --start 2026-10-11 --end 2026-10-11
```

精确到时分秒或核对全部记录：

```powershell
python launch.py --input "数据.xlsx" --invoice-audit "invoiceList_2026-10-24.xlsx" --start "2026-10-01 08:00" --end "2026-10-07 23:59:59"
python launch.py --input "数据.xlsx" --start= --end=
```

| 参数 | 用途 |
| --- | --- |
| `--input` | 输入 `.xlsx` 文件路径；无参数启动桌面界面 |
| `--invoice-audit` | 发票审核单 `.xlsx` 原文件；提供后过滤被红冲或无效的发票 |
| `--output-dir` | 输出目录；默认程序所在目录的 `outputs` |
| `--start` / `--end` | 开始及结束时间，格式与界面相同；不指定时默认均为 `2026-10-11`，两项空值表示全部；只空一项无效 |
| `--date` | 兼容旧版单日参数，`YYYY-MM-DD`；`--date=` 表示全部；不能与 `--start` / `--end` 混用 |
| `--red-only` | 结果工作簿打开时默认只显示加油异常记录，完整数据仍保留 |
| `--workers` | 并发工作数，`1`—`32`，默认 `20` |
| `--summary-json` | 将本次核对摘要另存为 UTF-8 JSON |

运行回归测试：

```powershell
python -m unittest discover -s tests -v
```

在 Windows 上首次准备持久的 `.venv` 环境（已有环境无需重复安装），此后直接打包 EXE：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

打包产物为 `dist/加华加油与发票核对助手.exe`。界面位于 `app.py`，命令行入口位于 `launch.py`，工作簿解析、核对与结果导出位于 `reconciliation.py`。
