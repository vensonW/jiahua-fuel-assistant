# 加华油站小助手

界面采用浅蓝底色、白色内容卡片和蓝色按钮，仅保留系统标题栏中的工具名称。窗口、详情和任务栏使用透明底加华星标；EXE 文件图标采用原来的红底 GAWA 英文字样。

将加油明细与发票逐笔核对，先在输入工作簿同目录保存核对前备份，再直接标注输入工作簿：加油原切页新增“失败原因”“关联发票号”，未配对发票在原发票切页标浅黄底，冲红票仍标浅红底；记账卡加油行仍标黄。油站切页只保存在结果工作簿，其中未配对发票也标浅黄底。结果工作簿和 `logs` 文件夹中的 `.log` 继续保留供复核。

GitHub 仓库包含源码、测试、品牌资源和构建脚本。原始业务工作簿、结果文件和 EXE 保留在本地，不随代码上传；从仓库获取代码后，请自行提供输入工作簿，按下方说明运行源码或打包 EXE。

## 使用 Windows 工具

1. 双击当前目录的 `加华加油与发票核对助手.exe`，运行 EXE 无需安装 Python。`dist` 内保留构建副本。
2. 点击“数据工作簿”旁的“浏览…”，选择包含加油及红蓝发票切页的 `.xlsx` 文件，无需另选发票审核单。开始核对前请关闭 Excel/WPS 中的源工作簿；若仍被占用，工具会立即提醒，点击“确定”后退出，不生成备份或结果。工具按表头识别切页，并从加油明细“交易时间”读取最早、最晚日期。待站点识别完成，在“审核站点”勾选一个或多个站点，也可全选；只核对所选站点。
3. 选择工作簿后，开始日期自动设为加油明细最早日期，截止时间默认为最晚日期的 `23:59:59`；日历也允许自由选择其他日期。勾选“指定时刻”后可选择时、分、秒。只选日期时，开始按当天 `00:00:00`、结束按当天最后一刻处理，包含两端边界；点击“全部加油日期”可恢复默认范围。若所选时间段没有可核对记录，程序会提示。
4. 同一工作簿发票切页中，红票备注指向的蓝票及红票自身、明确作废/无效的票均保留在对应油站切页并标红，但不参与配对；无站点且找不到对应蓝票的红票仍保留在发票原切页。若备注指向的蓝票不在表内，源文件和结果副本会新增“红冲配对结果”切页列出红票行号、票号、对应蓝票票号及缺失状态。确认输出目录，默认保存到工具所在目录的 `outputs` 文件夹，可通过“浏览…”另选位置。
5. 点击“开始核对”，读取阶段显示动态进度；匹配阶段按加油记录显示每轮已处理笔数（如 `5/97`），之后分别显示结果生成、保存与校验、原文件标注与校验的进度；全部完成后进度条才会填满。候选查找分三轮并发进行，默认按时间顺序一对一配对；同站同枪同油品同升数的记录仅在加油后60分钟内金额对应唯一时纠正交叉配对。完成后汇总区域及 `.log` 均显示核对耗时与分段耗时。程序“匹配失败”切页只显示核对未通过的加油明细及详细原因，可在“查找原始行号”输入如 `1698` 快速定位；“核对状态”下拉框仅列出加油明细出现的失败状态。成功与失败预览均按交易时间从早到晚显示，缺失时间的排在最后。“匹配成功”切页每对显示一条。点击“对应记录位置”可打开结果 Excel，双击其他列查看完整内容。
6. 点击“打开已标注原文件”，可在加油、发票原切页按底色查看异常；源文件的失败原因引用发票原切页行号。点击“打开结果工作簿”查看油站切页及完整核对结果；结果中的对应位置可跳转油站切页。未配对发票在发票原切页和结果油站切页整行标黄，冲红票标红，记账卡加油行仍标黄。点击“打开核对日志”查看失败详情。

预览筛选不会减少导出记录。输入工作簿每次覆盖前都生成避重名备份；重复运行时复用标注列并刷新旧标色。结果工作簿保存在输出目录，日志保存在其 `logs` 子目录，两者使用相同文件名主体；文件名采用生成时间而非筛选日期，如 `发票记录_核对结果_202610241458.xlsx`。新核对成功后，自动删除同一输入工作簿的旧核对 `.log`，保留其他文件和当前日志。

## 核对规则

- **应开票金额＝交易金额**：交易金额已扣除优惠，不再重复扣减。与发票“合计金额（含税）”按原始数值严格比较，不先四舍五入。开票方式为“手工开票”时，非零差额（包括 `0.01` 元）可保留疑似对应并标“金额不符”；其他开票方式（含空白）金额不一致时不作为配对候选，加油侧按“无对应记录”处理，关联发票号留空，未配对发票标黄。优惠金额仅供展示，不参与核对。
- 加油升数与发票数量必须完全相同，任何升数差额都不通过。
- 加油明细页“交易时间”与发票备注“交易时间”不设正向间隔上限；发票交易时间早于加油明细交易时间不超过 **10 分钟**（含边界）仍视为正常，超过 10 分钟显示“时间先后异常”。时间差仍如实展示，发票“开票时间”单独保留。
- 备注缺少结束时间时，允许使用开票时间辅助核对，并注明时间来源；“加油结束时间”仍留空。备注有时间但格式无效时标为待确认，不能把它当作缺失后直接回退。
- 从发票备注解析出的交易时间作为加油结束时间，供核对、程序预览和日志使用，同时写入结果 Excel 发票页“备注”右侧的“交易时间”列。备注缺失或无效时该列留空，不用开票时间代填。
- 优先根据备注油枪号及结束时间，结合加油表枪号、开始时间、油品和升数寻找对应记录；多油站数据须确认油站相符，不跨站配对。
- 同站、同枪号、同油品、同升数的重复候选默认按双方时间顺序配对；若已配对记录出现交叉，且每笔在加油后60分钟内仅有唯一金额完全相等的发票、每张发票也仅对应唯一加油记录，则在保持一对一和配对总数不变的前提下调整，并在配对依据中注明。存在重复金额或其他歧义时保持原顺序。有多余发票候选时，优先完整匹配的发票；每笔加油记录、每笔发票记录最多使用一次。
- 手工开票且其他信息能支持对应、但金额或其他规则不符时，可保留疑似对应位置及差额供核查；非手工发票必须金额相等才允许配对。**疑似对应不计为“已匹配”**。
- 加油和发票均未配对时，若站名相同或仅有“加油站/油站”等写法差异、金额相同、油品和升数不冲突，且发票时间在加油前 10 分钟至后 60 分钟内，并且双方候选均唯一，则在加油“失败原因”提示“疑似找到发票号”。提示仅供人工核对，不自动配对，“关联发票号”仍留空。
- 无法可靠判断、必需字段异常、同一发票多行或重复票号等情况标为“待确认”。所选时间段之外的记录直接跳过，不计入核对数量、异常、预览或日志；原始切页中的数据仍保留。
- “操作员”编号不构成免核对条件；包括 `999`、`9999` 在内的加油记录均按相同规则核对和标注。
- 同一已配对记录存在多项问题时，全部写入配对依据；手工开票的疑似对应只要金额存在差额，主状态显示“金额不符”。

| 核对状态 | 含义 |
| --- | --- |
| 已匹配 | 金额、升数完全相等，结束时间不早于开始时间超过 10 分钟，且配对依据成立 |
| 金额不符 | 存在对应或疑似对应，但实际发票金额与应开票金额存在差额 |
| 升数不符 | 存在疑似对应，但升数不同 |
| 时间先后异常 | 发票交易时间早于加油明细交易时间超过 10 分钟 |
| 无对应记录 | 未找到可靠对应记录 |
| 待确认 | 证据不足、字段异常、同票多行、重复票号等情况 |

除“已匹配”外，加油明细对应原行均标浅红底，付款类型为记账卡的行改用浅黄底；已匹配且付款类型为记账卡的行也标浅黄底。未配对发票原行和油站切页标浅黄底，冲红票标浅红底；已配对但存在差异的发票行不因此标色。未选站点和时间段外记录不新增标色或失败原因。

## 结果工作簿

输入工作簿保留原有可见切页，在加油明细页末尾新增或复用“失败原因”“关联发票号”两列；找到对应发票时填写完整票号，否则留空。疑似票号仅写入失败原因。加油、发票原切页的标签改为“加油明细记录{笔数}笔{金额}元”“发票记录{张数}张{金额}元”；两页只统计本次已匹配的记录及加油交易金额，数量、金额一致，金额保留两位小数，重复核对会刷新标题。发票原切页只标记未配对行，不新增字段。结果工作簿保留全部原始工作表及原始行顺序，也同步显示统计标题、两列标注和未配对发票黄底，并在发票页“备注”右侧插入“交易时间”列。每个所选站点仅在结果工作簿另增以站点名称命名的切页（不追加“发票”），按**开票时间**从早到晚复制时间段内的发票行，无有效开票时间的排在最后。重复核对旧版已标注文件时，会移除源文件中旧版生成的油站切页。

“匹配成功”页每对成功记录占一行，含站点、油枪、油品、加油量、交易时间、金额、发票号码及对应位置。“匹配失败”页只保存未通过的加油明细记录，列出状态、独立的“关联发票号”列、原因、金额及升数差异等；找不到关联发票时该列留空。原始行号和对应位置可点击跳转。这两页按加油交易时间升序，行号仍指向未排序的原始加油页。“发票未配对”页保存所选站点在时间段内未与加油明细配对的发票原始列，另列发票切页行号、油站、核对状态与未配对原因；该页按发票备注交易时间升序，行号则指向按开票时间排序后的站点切页。备注相同但票号不同的重复开票，未配对原因显示“重复发票：跟对应行是同一单”。字段异常的发票仍在该页列出，时间段外的发票跳过。新增切页不受界面筛选影响，首行均显示发票原切页的“资料区间”（含起止时间）；原切页没有该行时显示本次核对区间。其他原始字段、行高、列宽及已有批注保留，完整卡号和发票号码按原数据保留。

加油明细的异常原行（含新增两列）整行标浅红底，付款类型为记账卡的记录无论匹配结果均标浅黄底，并在表头启用筛选；匹配失败切页新增“付款类型”列，付款类型为记账卡的行也标黄。原表列名为“付款方式”时直接从该列读取。结果工作簿的发票页除新增交易时间列和未配对行黄底外，保留原有视图设置。

## 独立核对日志

每次核对同时输出 UTF-8 编码的 `.log`，保存在结果 `.xlsx` 所在目录的 `logs` 子目录，文件名主体相同。日志只记录匹配失败的两侧记录，包含状态、失败原因、对应位置、完整卡号与发票号码、付款类型、枪号、油品、三个时间、金额差、升数差、时间差和配对依据。

“已匹配”记录在程序的“匹配成功”切页按每对展示；程序“匹配失败”切页只展示加油明细的异常状态、失败原因、疑似对应和三个时间，其中“加油明细切页-交易时间”来自加油原表，“发票-交易时间”来自发票备注。状态筛选只列出加油明细出现的失败状态。

失败页显示“异常数量 / 加油总笔数”，成功页显示“成功数量 / 加油总笔数”。异常笔数为加油总笔数减成功笔数，失败页另显示筛选后的行数。结果工作簿的“匹配失败”页只保存加油明细失败记录，“发票未配对”页保存没有配对的发票，日志仍保存两侧失败记录。

- 金额差＝实际发票金额－应开票金额。
- 升数差＝发票升数－加油升数。
- 时间差＝加油结束时间－开始时间，以有符号分钟数展示；备注缺失时按注明的开票辅助时间计算。
- Excel 加油页支持按浅红底或浅黄底筛选；按状态筛选在程序预览中完成。
- “对应”按一对加油与发票计数；加油异常数和未配对发票数分别统计。

## 2026 年 10 月 11 日样例

旧版基于“交易金额－优惠金额”的统计不再适用。请导入实际工作簿重新核对；新规则直接以交易金额与发票金额比较，并要求加油量与发票数量完全相等。

核对 2026 年 10 月 1—7 日需要导入该期间实际数据，再将开始日期设为 `2026-10-01`、结束日期设为 `2026-10-07`；现有 10 月 11 日样例不能替代该期间数据。

## 源码运行与维护

使用带 Tkinter 的 Python 环境，在项目目录安装依赖后启动：

```powershell
python -m pip install -r requirements.txt
python launch.py
```

命令行也可执行核对：

```powershell
python launch.py --input "中南加华加油和开票数据核对.xlsx" --output-dir "outputs" --start 2026-10-11 --end 2026-10-11
```

精确到时分秒或核对全部记录：

```powershell
python launch.py --input "数据.xlsx" --start "2026-10-01 08:00" --end "2026-10-07 23:59:59"
python launch.py --input "数据.xlsx" --start= --end=
```

| 参数 | 用途 |
| --- | --- |
| `--input` | 输入 `.xlsx` 文件路径；无参数启动桌面界面 |
| `--invoice-audit` | 可选兼容参数；默认直接读取输入工作簿的发票切页，指定额外审核单时合并无效票号 |
| `--output-dir` | 输出目录；默认程序所在目录的 `outputs` |
| `--start` / `--end` | 开始及结束时间，格式与界面相同；不指定时默认均为 `2026-10-11`，两项空值表示全部；只空一项无效 |
| `--date` | 兼容旧版单日参数，`YYYY-MM-DD`；`--date=` 表示全部；不能与 `--start` / `--end` 混用 |
| `--red-only` | 结果工作簿打开时默认只显示加油异常记录，完整数据仍保留 |
| `--workers` | 并发工作数，`1`—`32`，默认 `20` |
| `--summary-json` | 将本次核对摘要另存为 UTF-8 JSON |

运行回归测试：

```powershell
python -m unittest discover -s tests -v
```

在 Windows 上首次准备持久的 `.venv` 环境（已有环境无需重复安装），此后直接打包 EXE：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
```

打包产物为 `dist/加华加油与发票核对助手.exe`。界面位于 `app.py`，命令行入口位于 `launch.py`，工作簿解析、核对与结果导出位于 `reconciliation.py`。

需要单独测量油站切页复制时，对**结果工作簿副本**运行 `python scripts/benchmark_station_copy.py <结果工作簿路径> <油站切页名> --repeat 3`；命令只在内存中复制并逐格核对，不修改工作簿。完整核对的分段耗时写在结果 `.log` 和界面摘要中；两次校验进一步区分工作簿加载与逐项检查。源文件的红冲配对结果页与已校验的结果工作簿快照逐格比对，不再为这一页重新加载整份结果工作簿。
